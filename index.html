Sistema Web para Gestión Centralizada de Solicitudes de Soporte

Se desarrollará una plataforma web destinada a optimizar y centralizar el proceso de solicitudes de soporte interno. Esta herramienta reemplazará los métodos informales actuales, como correos electrónicos o comunicación verbal, proporcionando un canal único y estructurado para la gestión de requerimientos.

Objetivos y Funcionalidades Principales:

  • Centralización de Solicitudes: Todas las solicitudes de soporte se registrarán y gestionarán a través de la plataforma.
  • Registro Eficiente: Los usuarios responsables de oficina podrán crear nuevas solicitudes, especificando la oficina afectada (pudiendo elegir entre las que tenga asignadas) y el tipo de soporte requerido (asociado a un rol de ejecutivo).
  • Gestión por el Administrador: El Administrador del Sistema será responsable de la configuración inicial y el mantenimiento de la plataforma. Esto incluye:
    • Creación y gestión de Oficinas.
    • Creación y gestión de Usuarios (tanto solicitantes como personal de soporte/ejecutivos).
    • Creación y gestión de Roles (ej. "Solicitante Oficina", "Ejecutivo de TI", "Ejecutivo de Logística", "Administrador"), asignando un color distintivo a los roles de atención para su visualización en el dashboard.
    • Asignación de usuarios a una o múltiples oficinas, permitiéndoles registrar solicitudes para estas.
    • Asignación de roles a los usuarios.
  • Dashboard de Monitoreo para Ejecutivos:
    • El personal de soporte (Ejecutivos) visualizará un dashboard con un listado de todas las oficinas.
    • Las oficinas con solicitudes activas (pendientes o en progreso) se destacarán con un color específico. Este color corresponderá al `color_dashboard` definido en el rol del ejecutivo requerido para atender dicha solicitud.
    • Al hacer clic en una oficina "pintada" (o en su indicador de color), se mostrará el detalle de las solicitudes pendientes que requieren atención del rol del ejecutivo logueado.
    • Una vez una solicitud es gestionada y completada (resuelta/cerrada), el indicador de color correspondiente en el dashboard se actualizará o "despintará".
  • Gestión de Solicitudes por Ejecutivos: Los ejecutivos podrán asignarse solicitudes, actualizar su estado (ej. "En Progreso", "Resuelta"), registrar la solución aplicada y cerrar los casos.
  • Trazabilidad y Comunicación: Se mantendrá un historial completo de cada solicitud, incluyendo comentarios y cambios de estado, mejorando la transparencia y la comunicación entre solicitantes y ejecutivos.

Este sistema busca mejorar significativamente la eficiencia, organización y seguimiento del soporte interno, proporcionando una herramienta robusta tanto para los usuarios que solicitan ayuda como para el personal encargado de brindarla.

Tipos de Relaciones Principales entre Tablas

  • Usuarios y Roles: Muchos-a-Muchos (*..*). Un usuario puede tener varios roles, y un rol puede ser asignado a varios usuarios (mediante `UsuarioRoles`).
  • Usuarios y Oficinas: Muchos-a-Muchos (*..*). Un usuario puede estar asignado a varias oficinas para registrar solicitudes, y una oficina puede tener varios usuarios asignados (mediante `UsuarioOficina`).
  • Usuarios y Solicitudes (como solicitante): Uno-a-Muchos (1..*). Un usuario puede crear muchas solicitudes. Cada solicitud tiene un único usuario solicitante.
  • Roles y Solicitudes (como rol de atención): Uno-a-Muchos (1..*). Un rol (ej. "Ejecutivo de Soporte TI") puede ser el responsable de atender muchas solicitudes. Cada solicitud se dirige a un rol de atención específico, cuyo color se usará en el dashboard.
  • Oficinas y Solicitudes: Uno-a-Muchos (1..*). Una oficina puede tener muchas solicitudes. Cada solicitud pertenece a una oficina afectada.
  • Usuarios y Solicitudes (como asignado): Uno-a-Muchos (1..*). Un usuario (ejecutivo) puede tener muchas solicitudes asignadas. Cada solicitud (si está asignada) tiene un único usuario asignado.
  • Solicitudes y ComentariosSolicitud: Uno-a-Muchos (1..*). Una solicitud puede tener muchos comentarios. Cada comentario pertenece a una única solicitud.
  • Usuarios y ComentariosSolicitud (como autor): Uno-a-Muchos (1..*). Un usuario puede escribir muchos comentarios. Cada comentario tiene un único autor.
